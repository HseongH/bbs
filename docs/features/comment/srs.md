# 댓글 요구사항 명세서

> [프로젝트 SRS](../../project/srs.md)의 공통 요구사항(`COM-*`)을 모두 상속한다. 이 문서는 댓글 기능에 고유한 요구사항만 담는다.

## 1. 개요

### 1.1 목적

회원이 게시글에 의견을 남기고 다른 댓글에 답할 수 있게 한다. 답글은 한 단계까지만 허용해서 대화가 지나치게 깊어지지 않게 한다.

### 1.2 범위

| 포함 | 제외 |
|---|---|
| 원댓글 작성, 대댓글(답글) 1단계 | 2단계 이상의 답글 |
| 게시글별 댓글 목록 | 댓글 좋아요, 멘션, 알림 |
| 본인 댓글 수정, 본인·관리자 삭제 | 댓글 신고, 숨김 |
| 게시글 상세 화면의 댓글 영역 | 내가 쓴 댓글 모아 보기 |

### 1.3 다른 기능과의 관계

| 관계 | 내용 |
|---|---|
| 게시글(`PST`) | 댓글은 게시글에 속한다. 삭제된 게시글에는 댓글을 달 수 없다. 게시글이 삭제되면 그 댓글도 함께 삭제된다 (PST-FR-006, CMT-FR-007). |
| 회원(`MEM`) | 작성자는 회원이다. |

## 2. 데이터 항목

| 항목 | 규칙 | 근거 |
|---|---|---|
| 본문 | 필수. 앞뒤 공백을 제거한 뒤 1~1,000자 | 짧은 의견 표현에 충분한 길이 |
| 게시글 | 댓글이 속한 게시글. 작성 후 바뀌지 않는다 | |
| 부모 댓글 | 대댓글이면 원댓글의 식별자, 원댓글이면 없음 | |
| 깊이 | 원댓글 0, 대댓글 1. 그 밖의 값은 허용하지 않는다 | 대화 깊이 제한 |
| 작성자, 작성 시각 | 서버가 기록한다 | |

## 3. 기능 요구사항

### 3.1 작성

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| CMT-FR-001 | 회원은 게시글에 댓글을 작성할 수 있다. | 성공하면 `201`과 `Location: /api/comments/{id}`를 반환하고 깊이는 0이다. 존재하지 않거나 삭제된 게시글이면 `404 POST_NOT_FOUND`이다. 비회원은 `401`, 본문 규칙 위반은 `400 INVALID_REQUEST`이다. |
| CMT-FR-002 | 회원은 원댓글에 답글(대댓글)을 작성할 수 있다. | 부모 댓글을 지정하면 깊이 1로 기록된다. 부모 댓글이 없거나 삭제되었으면 `404 COMMENT_NOT_FOUND`이다. |
| CMT-FR-003 | 대댓글에는 답글을 달 수 없다. | 깊이 1인 댓글을 부모로 지정하면 `400 COMMENT_DEPTH_EXCEEDED`이다. 데이터베이스에도 깊이 0~1만 저장할 수 있다. |
| CMT-FR-008 | 대댓글의 부모 댓글은 같은 게시글에 속해야 한다. | 다른 게시글의 댓글을 부모로 지정하면 거부한다. **현재 미구현** (§6 CMT-OPEN-01). |

### 3.2 조회

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| CMT-FR-004 | 누구나 게시글의 댓글 목록을 페이지 단위로 조회할 수 있다. | 삭제된 댓글은 나오지 않는다. 작성 순(오래된 것부터)이며, 작성 시각이 같으면 식별자 순이다. 기본 페이지 크기는 20이다. 원댓글과 대댓글이 한 목록에 함께 나오며, 각 항목에 부모 식별자와 깊이가 있다. |

### 3.3 수정과 삭제

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| CMT-FR-005 | 작성자는 자신의 댓글 본문을 수정할 수 있다. | 성공하면 `204`이다. 작성자가 아니면 관리자라도 `403 ACCESS_DENIED`이다. 삭제된 댓글은 `404 COMMENT_NOT_FOUND`이다. |
| CMT-FR-006 | 작성자 또는 관리자는 댓글을 삭제할 수 있다. | 성공하면 `204`이고 소프트 삭제된다. 이미 삭제된 댓글은 `404`이다. |
| CMT-FR-007 | 게시글이 삭제되면 그 게시글의 삭제되지 않은 댓글이 모두 같은 시각으로 삭제된다. | 게시글 삭제와 같은 트랜잭션에서 처리되어, 게시글 삭제가 실패하면 댓글도 삭제되지 않는다. |

### 3.4 화면

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| CMT-FR-020 | 게시글 상세 화면에 댓글과 대댓글을 함께 보여 준다. | 대댓글은 들여쓰기로 구분한다. |
| CMT-FR-021 | 로그인한 사용자는 댓글 입력란에서 댓글을 등록할 수 있다. | 등록에 성공하면 입력란을 비운다. |
| CMT-FR-022 | 원댓글에만 답글 버튼을 보여 준다. | 대댓글에는 답글 버튼이 없다. |
| CMT-FR-023 | 수정·삭제 버튼은 작성자 본인에게만 보여 준다. | |

## 4. 비기능 요구사항

공통 비기능 요구사항 외에 댓글 기능에 고유한 요구사항은 없다.

## 5. 인터페이스

| 메서드 | 경로 | 요구사항 | 인증 | 성공 |
|---|---|---|---|---|
| `POST` | `/api/posts/{postId}/comments` | CMT-FR-001, 002, 003 | 필요 | `201` |
| `GET` | `/api/posts/{postId}/comments` | CMT-FR-004 | 불필요 | `200` |
| `PATCH` | `/api/comments/{id}` | CMT-FR-005 | 필요 | `204` |
| `DELETE` | `/api/comments/{id}` | CMT-FR-006 | 필요 | `204` |

## 6. 미결 사항

| 번호 | 내용 | 영향 | 제안 |
|---|---|---|---|
| CMT-OPEN-01 | 대댓글 작성 시 부모 댓글이 같은 게시글에 속하는지 검사하지 않는다 (CMT-FR-008). | 게시글 A의 댓글을 부모로 지정해 게시글 B에 대댓글을 달 수 있다. 화면 표시가 어긋난다. | `Comment.write`에서 부모의 게시글과 대상 게시글이 같은지 검사한다. 위반 시 오류 코드를 정한다 (`INVALID_REQUEST` 또는 신규 코드). |
| CMT-OPEN-02 | 원댓글이 삭제되어도 그 대댓글은 남는다. 남은 대댓글을 어떻게 보여 줄지 정의되지 않았다. | 목록에 부모가 없는 대댓글이 나온다. | "삭제된 댓글입니다" 자리 표시를 둘지, 대댓글도 함께 삭제할지 결정한다. |
| CMT-OPEN-03 | 목록이 작성 시각 순서의 평면 목록이고, 화면은 그 순서대로 대댓글을 들여 쓴다. | 나중에 단 대댓글이 원래 부모가 아닌 다른 원댓글 아래에 있는 것처럼 보인다. | 서버가 원댓글 단위로 묶어 정렬하거나, 화면이 `parentCommentId`로 묶어서 보여 준다. |
| CMT-OPEN-04 | 댓글 응답에 작성자 닉네임이 없다. | 화면이 작성자를 이름으로 보여 줄 수 없다. | 게시글 목록처럼 조인 프로젝션을 사용한다. |
| CMT-OPEN-05 | 존재하지 않거나 삭제된 게시글의 댓글 목록을 요청하면 `404`가 아니라 빈 목록을 반환한다. | 클라이언트가 게시글 부재를 구분할 수 없다. | 현재 동작을 유지할지 결정하고 문서화한다. |
