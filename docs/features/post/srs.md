# 게시글 요구사항 명세서

> [프로젝트 SRS](../../project/srs.md)의 공통 요구사항(`COM-*`)을 모두 상속한다. 이 문서는 게시글 기능에 고유한 요구사항만 담는다.

## 1. 개요

### 1.1 목적

회원이 게시글을 작성·수정·삭제하고, 누구나 게시글을 찾아 읽을 수 있게 한다. 조회수와 좋아요로 게시글의 반응을 보여 준다.

### 1.2 범위

| 포함 | 제외 |
|---|---|
| 작성, 상세 조회, 수정, 삭제 | 첨부파일, 이미지 |
| 목록, 키워드·작성자 검색, 페이지 | 카테고리, 태그, 정렬 기준 선택 |
| 조회수, 좋아요·좋아요 취소 | 임시 저장, 예약 게시 |
| 목록·상세·작성·수정 화면 | 수정 이력, 신고 |

### 1.3 사용자와 권한

[프로젝트 SRS §3.1 권한 매트릭스](../../project/srs.md#31-권한-매트릭스)를 따른다. 게시글 기능에서 특히 주의할 규칙은 **관리자도 다른 사람의 글을 수정할 수는 없다**는 것이다. 관리자는 삭제만 할 수 있다.

## 2. 데이터 항목

| 항목 | 규칙 | 근거 |
|---|---|---|
| 제목 | 필수. 앞뒤 공백을 제거한 뒤 1~100자 | 목록 화면의 한 줄 표시 |
| 본문 | 필수. 공백만으로 이루어질 수 없다. 1~10,000자. 앞뒤 공백을 제거하지 않는다 | 본문의 들여쓰기와 줄바꿈 보존 |
| 작성자 | 작성한 회원. 작성 후 바뀌지 않는다 | |
| 조회수 | 0부터 시작. 음수가 될 수 없다 | |
| 좋아요 수 | 0부터 시작. 음수가 될 수 없다 | |
| 작성 시각 | 서버가 기록한다 | |

## 3. 기능 요구사항

### 3.1 작성과 조회

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| PST-FR-001 | 회원은 제목과 본문을 입력해 게시글을 작성할 수 있다. | 성공하면 `201`과 `Location: /api/posts/{id}`를 반환한다. 조회수와 좋아요 수는 0이다. 비회원은 `401`, 규칙 위반은 `400 INVALID_REQUEST`와 필드별 오류를 반환한다. |
| PST-FR-002 | 누구나 게시글 하나를 상세 조회할 수 있다. | 응답에 식별자, 제목, 본문, 작성자 식별자, 조회수, 좋아요 수, 작성 시각이 있다. 존재하지 않거나 삭제된 게시글은 `404 POST_NOT_FOUND`이다. |
| PST-FR-003 | 상세 조회 시 조회수가 1 오른다. 같은 사용자가 24시간 안에 다시 조회하면 오르지 않는다. | 사용자 구분은 회원이면 회원 식별자, 비회원이면 세션으로 한다. 응답의 조회수는 이번 조회가 반영되기 전 값이다. 조회수 반영이 실패해 롤백되면 그 조회는 기록되지 않은 것으로 보고, 같은 사용자의 다음 조회를 다시 센다. |

### 3.2 목록과 검색

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| PST-FR-004 | 누구나 게시글 목록을 페이지 단위로 조회할 수 있다. | 삭제된 게시글은 나오지 않는다. 최신 작성 순이며, 작성 시각이 같으면 식별자가 큰 순이다. 기본 페이지 크기는 20이다. 각 항목에는 본문이 없고 작성자 닉네임이 있다. |
| PST-FR-009 | 키워드로 게시글을 검색할 수 있다. | 키워드는 제목 **또는** 본문에 대소문자 구분 없이 포함되면 일치한다. 키워드의 앞뒤 공백은 제거하고, 공백뿐이면 조건에서 제외한다. |
| PST-FR-010 | 작성자로 게시글을 걸러 볼 수 있다. | `authorId`를 지정하면 그 회원의 게시글만 나온다. 키워드와 함께 지정하면 두 조건을 모두 만족해야 한다. |

### 3.3 수정과 삭제

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| PST-FR-005 | 작성자는 자신의 게시글 제목과 본문을 수정할 수 있다. | 성공하면 `204`이다. 작성자가 아니면 관리자라도 `403 ACCESS_DENIED`이다. 삭제된 게시글은 `404`이다. 입력 규칙은 작성과 같다. |
| PST-FR-006 | 작성자 또는 관리자는 게시글을 삭제할 수 있다. | 성공하면 `204`이다. 삭제는 소프트 삭제이며, **게시글에 달린 댓글도 함께 삭제된다.** 게시글 삭제가 실패하면 댓글도 삭제되지 않는다. 이미 삭제된 게시글은 `404`이다. |
| PST-FR-011 | 수정과 삭제는 그 사이에 다른 사용자가 올린 조회수와 좋아요 수를 잃지 않는다. | 게시글을 불러온 뒤 다른 요청이 카운터를 올리고 나서 수정해도, 수정 후의 카운터에 그 증가분이 남아 있다. |

### 3.4 좋아요

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| PST-FR-007 | 회원은 게시글에 좋아요를 한 번 누를 수 있다. | 성공하면 `204`이고 좋아요 수가 1 오른다. 이미 좋아요한 게시글이면 `409 ALREADY_LIKED`이다. 존재하지 않거나 삭제된 게시글은 `404`이다. |
| PST-FR-008 | 회원은 자신의 좋아요를 취소할 수 있다. | 성공하면 `204`이고 좋아요 수가 1 내려간다. 좋아요하지 않은 게시글이면 `409 NOT_LIKED`이다. |

### 3.5 화면

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| PST-FR-020 | 목록 화면은 제목, 작성자, 페이지 이동, 검색을 제공한다. | 검색 조건과 페이지가 URL에 남아서, 새로고침하거나 링크를 공유해도 같은 결과가 나온다. 결과가 없으면 안내 문구를 보여 준다. 현재 페이지 버튼은 보조 기술에 현재 위치로 알린다. 목록을 불러오지 못하면 안내 문구를 보여 준다. |
| PST-FR-021 | 상세 화면은 제목, 본문, 좋아요 버튼, 댓글 영역을 보여 준다. | 수정·삭제 버튼은 작성자 본인에게만 보인다. 없는 글이면 안내 문구를 보여 준다. |
| PST-FR-022 | 작성·수정 화면은 로그인한 사용자만 들어갈 수 있다. | 비로그인 상태로 들어가면 로그인으로 이동한다. 수정 화면은 기존 값이 채워진 상태로 열린다. |
| PST-FR-023 | 서버가 검증 오류를 반환하면 해당 입력란 아래에 메시지를 보여 준다. | 필드별 오류가 있으면 전체 오류 메시지를 겹쳐 보여 주지 않는다. |
| PST-FR-024 | 좋아요를 누르면 숫자가 즉시 올라간다. | 이미 좋아요한 글이면(`409 ALREADY_LIKED`) 안내 문구를 보여 준다. |
| PST-FR-025 | 화면마다 브라우저 제목이 그 화면을 나타낸다. | 목록·작성·상세·수정·찾을 수 없음 화면의 제목이 서로 다르고, 사이트 이름(게시판)을 함께 표시한다. 화면을 옮기면 제목도 바뀌어 보조 기술이 화면 전환을 알 수 있다. |

## 4. 비기능 요구사항

공통 비기능 요구사항(`COM-NFR-*`) 외에 게시글 기능에 고유한 요구사항이다.

| ID | 요구사항 | 검증 |
|---|---|---|
| PST-NFR-001 | 같은 회원이 같은 게시글에 동시에 여러 번 좋아요를 요청해도 좋아요는 1건, 좋아요 수는 1이다. 동시에 여러 번 취소해도 좋아요 수는 0 아래로 내려가지 않는다. | 동시성 테스트 |
| PST-NFR-002 | 목록 조회는 페이지당 데이터 쿼리 1회와 건수 쿼리 1회로 처리한다. 작성자 수만큼 추가 쿼리가 발생하지 않는다. | 설계 검토 (조인 프로젝션) |

## 5. 인터페이스

| 메서드 | 경로 | 요구사항 | 인증 | 성공 |
|---|---|---|---|---|
| `POST` | `/api/posts` | PST-FR-001 | 필요 | `201` |
| `GET` | `/api/posts` | PST-FR-004, 009, 010 | 불필요 | `200` |
| `GET` | `/api/posts/{id}` | PST-FR-002, 003 | 불필요 | `200` |
| `PATCH` | `/api/posts/{id}` | PST-FR-005 | 필요 | `204` |
| `DELETE` | `/api/posts/{id}` | PST-FR-006 | 필요 | `204` |
| `POST` | `/api/posts/{id}/likes` | PST-FR-007 | 필요 | `204` |
| `DELETE` | `/api/posts/{id}/likes` | PST-FR-008 | 필요 | `204` |

요청·응답 형식의 상세는 [게시글 SDS §4](sds.md#4-인터페이스-설계)에 있다.

## 6. 미결 사항

| 번호 | 내용 | 영향 |
|---|---|---|
| PST-OPEN-01 | 상세 응답에 작성자 닉네임이 없다. 목록에는 있다. | 화면이 상세에서 작성자 이름을 보여 주려면 추가 요청이 필요하다. |
| PST-OPEN-02 | 현재 회원이 이 글에 좋아요를 눌렀는지 알려 주는 필드가 없다. | 화면은 좋아요를 누른 뒤 `409` 응답으로만 중복을 알 수 있다. 좋아요 취소 버튼을 화면에 제공하지 못한다. |
| PST-OPEN-03 | 수정 시각을 응답에 담지 않는다. | 사용자가 글이 수정되었는지 알 수 없다. |
