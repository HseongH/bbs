# 게시판(bbs) Project Charter

> 개인 학습 프로젝트이므로 PMBOK의 Project Charter를 한두 쪽 분량으로 줄였다. 예산과 조직 승인 항목은 제외하고, 범위를 통제하는 데 필요한 항목만 남겼다.

## 1. 배경과 목적

엔터프라이즈 환경에서 요구되는 개발 방식(설계 합의, 계층 분리, 자동화된 품질 게이트, 문서화)을 작은 규모에서 처음부터 끝까지 연습한다.

게시판은 도메인이 단순해서 업무 규칙을 이해하는 데 시간을 쓰지 않고도 **권한, 동시성, 페이징, 인증, 기능 사이의 의존** 같은 실무 문제를 모두 다룰 수 있다. 그래서 학습 소재로 선택했다.

## 2. 목표와 성공 기준

| 목표 | 성공 기준 (측정 방법) |
|---|---|
| 설계 의도가 코드로 강제된다 | 아키텍처 규칙 위반 시 `./gradlew check`가 실패한다 (ArchUnit) |
| 품질 기준이 자동으로 지켜진다 | 포맷, 정적 분석, null 안정성, 커버리지 중 하나라도 미달이면 CI가 실패한다 |
| 규칙에 우회 경로가 없다 | 제목 길이, 답글 깊이, 수정·삭제 권한이 모두 도메인 테스트로 검증된다 |
| 동시성 문제가 데이터베이스 수준에서 처리된다 | 동시 요청 테스트에서 좋아요와 카운터가 정확하다 |
| 다른 프로젝트에서 참고할 수 있는 문서를 남긴다 | 이 문서 체계를 템플릿만으로 다른 프로젝트에 적용할 수 있다 |

## 3. 범위

### 3.1 포함

- 게시글: 작성, 조회, 수정, 삭제, 목록, 검색, 조회수, 좋아요
- 댓글: 작성, 목록, 수정, 삭제, 대댓글 1단계
- 회원·인증: Keycloak 로그인, 최초 로그인 시 회원 자동 생성, 내 정보 조회
- 화면: 위 기능을 사용하는 SPA (Angular)
- 로컬 실행 환경과 CI

### 3.2 제외

| 항목 | 제외 이유 |
|---|---|
| 첨부파일 업로드 | 학습 목표(계층 분리, 동시성)와 관련이 적고 저장소 인프라가 추가로 필요하다 |
| 관리자 백오피스 | 관리자 권한은 "다른 사람의 글 삭제"만으로 충분히 연습할 수 있다 |
| 알림, 검색 엔진 연동 | 외부 시스템 연동이 늘어나 범위가 커진다 |
| 운영 배포 | 로컬 실행과 CI까지만 다룬다 |
| 회원 정보 수정 화면 | 도메인 메서드(`changeNickname`)만 두고 화면과 API는 만들지 않는다 |

## 5. 제약 조건

- 1인 개발이다. 리뷰어가 없으므로 자동화된 검사와 문서의 자체 검토 절차로 이를 보완한다.
- 기술 스택은 학습 목적에 맞춰 최신 LTS·안정 버전을 사용한다 (상세는 [프로젝트 SDS](sds.md) §2).
- 로컬 환경은 Docker Compose만으로 재현 가능해야 한다.

## 7. 주요 위험

| 위험 | 영향 | 대응 |
|---|---|---|
| 1인 개발이라 설계 오류를 지적할 사람이 없다 | 잘못된 구조가 누적된다 | ArchUnit으로 구조를 강제하고, 설계 결정을 ADR로 남겨 나중에 재검토한다 |
| 최신 버전 라이브러리의 호환성 문제 | 빌드가 깨진다 | 호환성 문제를 ADR로 기록한다 (예: [ADR-0006](adr/0006-querydsl-openfeign-fork.md)) |
| 문서가 코드보다 뒤처진다 | 문서를 믿을 수 없게 된다 | 코드와 문서를 같은 PR에서 리뷰하고, 규칙은 문서가 아니라 테스트로 강제한다 |
