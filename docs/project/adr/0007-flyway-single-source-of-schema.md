# ADR-0007. 스키마는 Flyway가 유일한 출처다

- 상태: Accepted
- 일자: 2026-09-18
- 관련: COM-CON-005, COM-NFR-013

## 맥락

JPA의 `ddl-auto: update`는 편리하지만 어떤 DDL이 실행되는지 통제할 수 없고, 제약 조건이나 부분 인덱스 같은 세밀한 스키마를 표현하기 어렵다. 엔티티와 스키마 중 무엇이 기준인지도 모호해진다.

## 결정

- 스키마 변경은 `src/main/resources/db/migration/V{n}__{설명}.sql` Flyway 스크립트로만 한다.
- JPA는 `ddl-auto: validate`로 엔티티와 스키마가 일치하는지 검증만 한다.
- 도메인 규칙 중 데이터 손상으로 이어지는 규칙은 DB 제약으로 한 번 더 막는다 (댓글 깊이 `CHECK`, 좋아요 `UNIQUE`).
- 이미 적용된 마이그레이션 파일은 수정하지 않는다. 변경은 새 버전 파일로 추가한다.

## 결과

- 좋은 점: 스키마 변경 이력이 코드 리뷰 대상이 된다. 부분 인덱스, `CHECK` 제약 같은 DB 기능을 자유롭게 쓴다.
- 나쁜 점: 엔티티와 마이그레이션을 함께 수정해야 한다. 어긋나면 애플리케이션이 시작되지 않는다 (의도된 동작).
