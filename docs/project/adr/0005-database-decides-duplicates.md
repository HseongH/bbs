# ADR-0005. 중복 판정은 저장소에 맡긴다

- 상태: Accepted (조회수 키 저장소 제품은 [ADR-0013](0013-valkey-instead-of-redis.md)으로 대체)
- 일자: 2026-09-18
- 관련: COM-NFR-011, PST-FR-007, PST-FR-003

## 맥락

같은 회원이 같은 게시글에 좋아요를 두 번 누르면 안 되고, 같은 사용자가 같은 게시글을 짧은 시간에 여러 번 열어도 조회수는 한 번만 올라야 한다. "먼저 조회하고 없으면 저장"하는 방식은 두 요청이 동시에 조회를 통과할 수 있다. 또한 저장 시 유니크 제약 위반 예외가 발생하면 진행 중인 트랜잭션 전체가 롤백 전용 상태가 된다.

## 결정

- **좋아요**: `(post_id, member_id)` 유니크 제약을 두고 `INSERT ... ON CONFLICT DO NOTHING`으로 저장한다. 영향받은 행 수가 0이면 이미 좋아요한 것으로 판정한다. 취소도 `DELETE`의 영향받은 행 수로 판정한다.
- **조회수**: Redis `SET key value NX EX 86400`(`setIfAbsent`)으로 24시간 동안 같은 사용자의 중복 조회를 판정한다. 키는 회원이면 `m{memberId}`, 비회원이면 `s{sessionId}`를 사용한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 조회 후 저장 (check-then-act) | 동시 요청에서 중복이 생긴다 |
| 제약 위반 예외를 잡아서 처리 | 트랜잭션이 롤백 전용 상태가 되어 같은 트랜잭션의 다른 작업을 할 수 없다 |
| 조회 기록을 DB 테이블에 저장 | 조회는 쓰기 빈도가 높고 영구 보관할 필요가 없다. TTL이 있는 Redis가 적합하다 |

## 결과

- 좋은 점: 동시 요청에서도 정확하고, 예외 없이 결과로 판정한다.
- 나쁜 점: `ON CONFLICT`는 PostgreSQL 전용 문법이므로 네이티브 쿼리를 쓴다. DB를 바꾸면 이 쿼리도 바꿔야 한다.
- 나쁜 점: 비회원의 조회수 판정에 세션 ID를 쓰므로, 비회원이 게시글을 조회하면 세션이 생성되어 Redis에 저장된다.
