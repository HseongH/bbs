# ADR-0003. 소유권 검사는 도메인에 둔다

- 상태: Accepted
- 일자: 2026-09-18
- 관련: COM-NFR-005, PST-FR-005, PST-FR-006, CMT-FR-005, CMT-FR-006

## 맥락

"작성자만 수정할 수 있다", "관리자는 삭제만 할 수 있고 수정은 할 수 없다" 같은 규칙을 어디에 둘지 정해야 한다. 서비스나 컨트롤러에 두면, 같은 도메인 객체를 바꾸는 새 경로(배치, 다른 유스케이스)가 생겼을 때 검사를 빠뜨릴 수 있다.

## 결정

- 소유권과 삭제 상태 검사는 도메인 메서드 안에서 수행한다. (`post.updateBy(requester, ...)`, `post.deleteBy(requester, admin, now)`)
- 역할(관리자 여부)은 컨트롤러가 `Authentication`에서 읽어 `boolean`으로 전달한다. 도메인은 스프링 보안 타입을 모른다.
- 서비스는 조율(불러오기 → 도메인 메서드 호출 → 저장)만 하고 권한을 판단하지 않는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| `@PreAuthorize` + SpEL로 소유권 검사 | 규칙이 어노테이션 문자열에 숨는다. 도메인 테스트로 검증할 수 없다 |
| 서비스에서 검사 | 서비스를 거치지 않는 경로가 생기면 규칙이 새어 나간다 |

## 결과

- 좋은 점: 권한 규칙을 도메인 단위 테스트로 빠르게 검증한다 (`PostTest`, `CommentTest`). 우회 경로가 없다.
- 나쁜 점: 도메인 메서드의 파라미터에 요청자 정보가 들어간다.
- 미결: 역할 수준 인가(`USER` 역할 보유 여부)는 하지 않는다. [프로젝트 SRS](../srs.md#7-미결-사항) OPEN-03 참고.
